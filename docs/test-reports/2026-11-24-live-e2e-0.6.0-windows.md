# Live end-to-end test: gh-ledger 0.6.0 on Windows 11

On 2026-11-24, the gh-ledger 0.5.0 extension installed by the [0.5.0 test](2026-11-24-live-e2e-windows.md) was upgraded to 0.6.0 on the same Windows 11 machine, following the upgrade steps in [Install and uninstall](../cli.md#install-and-uninstall), and tested end to end:
- the upgrade itself, with the binary's checksum and build provenance attestation;
- the repair import that moves 0.5.0's history to Copilot's reported charges;
- a reconciliation of the ledger with Copilot's own per-request charges;
- live prompts through Copilot CLI 1.0.115;
- every report, the MCP server, audit, exports, and receipts, timed against the 0.5.0 test;
- the documented way back to 0.5.0, in a sandbox;
- a privacy audit of everything gh-ledger wrote.

0.6.0 closes all 10 issues in the 0.5.0 test's list of gaps, and this test checked each fix on the machine where it was found. It found three smaller gaps, each filed as an issue.

The machine owner's own history appears only as counts and percentages, and the only repository named is this one. The live prompts' own spend is shown in full: 8.4649042 AI credits ($0.08).

## Environment

- **Machine:** Windows 11 Pro 10.0.26300, x64, with GitHub CLI 2.103.3: the machine of the 0.5.0 test.
- **Copilot CLI:** the WinGet package, auto-updated to 1.0.115. All three prompts ran 1.0.115. The GitHub Copilot app was also in use on the same machine.
- **Before the upgrade:** gh-ledger 0.5.0 was installed as the extension, and its daemon ran outside any job, on port 4318. The ledger was at format 6, 101 MB, with 61,323 imported and 21 live requests.
- **Copilot's session store:** 308 sessions with an `events.jsonl` after the live prompts.

## Method

As in the 0.5.0 test:
- **Live prompts** ran `copilot -p <prompt> --model <model> --session-id <new GUID>` from this repository's working tree, as a new terminal would: with no `COPILOT_*`, `OTEL_*`, `GH_TOKEN`, or `GITHUB_TOKEN` variables except the user-scope `COPILOT_OTEL_ENABLED=true`, and with the real `~/.copilot` and the stored login.
- **Each charge was compared** with the CLI's `AI Credits` line, with the ledger's rows read with SQLite in read-only mode, and with the session log's `copilotUsage.totalNanoAiu`, where 1 AI credit is 10^9 nano AIU.
- **The checks were small, read-only Python scripts.** They read only the metadata fields named below and printed only aggregates. They aren't in the repository, which allows no Python.

- **Totals agree:**

  - The receipt's 30 turns and 30.8134117 AI credits equal the branch's row in `branch --since all --json`. Its heading is `### gh-ledger receipt for`, and its check line names `gh ledger branch --since all --json`.

## Privacy

**Content samples.** 500 samples, 100 each from user messages, assistant messages and reasoning, tool arguments, tool results, and compaction summaries. All came from the 87 sessions that gh-ledger imported or recorded live, including the 3 live prompts. Each was a 40-character excerpt with at least two spaces, searched for as UTF-8, as escaped JSON, and as UTF-16, in 93 files and archive entries, 276.5 MB in all:
- `ledger.db`, `ledger.db-wal`, `ledger.db-shm`, `daemon.log`, `install.json`, and `daemon.json`;
- the 4 HTML reports and every entry of the 2 bundles;
- the saved output of every command, import, and MCP tool above.

**None was found.**

**Ledger columns.** No text value in `spans` or `span_links` has two or more spaces. The longest are local repository roots, as documented, and the 129-character MCP tool names of [#90](https://github.com/swigerb/gh-ledger/issues/90).

**Reports.** Every HTML report has its Content Security Policy. None contains `http://`, `https://`, `<script src`, or `<link`.

**Local paths.** No export, bundle entry, receipt, audit output, or MCP result contains the user's profile path. Only `status` (the ledger's path) and `rates validate` (the overlay's path) print it, in the terminal.

**Live spans.** Copilot's content capture was off, its default: the CLI's log shows `capture_prompts`, `capture_responses`, `capture_tool_arguments`, and `capture_tool_output` as `false`.

## Gaps found

| Issue | Severity | Gap |
|---|---|---|
| [#90](https://github.com/swigerb/gh-ledger/issues/90) | Low | MCP tool calls recorded live are named by Copilot's hashes, `sha256(server)/sha256(tool)`, on the export timeline and in audit findings. The session log has the readable name. |
| [#91](https://github.com/swigerb/gh-ledger/issues/91) | Low | `install --dry-run` always says it would start the daemon, even when it's running, or when the terminal's job would make `install` refuse with exit code 1. |
| [#92](https://github.com/swigerb/gh-ledger/issues/92) | Low | `--help` usage lines name `gh-ledger`, which isn't on `PATH` for the extension. |

**Update:** gh-ledger 0.7.0 fixes all three: [#90](https://github.com/swigerb/gh-ledger/issues/90), [#91](https://github.com/swigerb/gh-ledger/issues/91), and [#92](https://github.com/swigerb/gh-ledger/issues/92).

**The test suite.** While this report was being merged, CI failed `SL10_AnotherProcessAppliesMigrationFirst` on Ubuntu with `duplicate column name: list_cost_usd_pico`. That test and `V115_8_Unread115AndMessageFieldsKeepTheirCanariesPrivate` passed only when a test running in parallel happened to clear SQLite's connection pool. Run alone, or with `dotnet test CopilotLedger.slnx -- xUnit.ParallelizeTestCollections=false`, each failed every time: SL10 migrated on a pooled connection that had cached the schema from before the test dropped columns, and V115_8 read `ledger.db` while a pooled connection held it open on Windows. Both now clear the pool first, as the suite's other tests do, and the whole suite passes either way.

**Not gh-ledger gaps.**
- **Cleartext export:** the [OpenTelemetry reference](https://docs.github.com/en/copilot/reference/enterprise-administrators/opentelemetry-reference) says that an `http://` endpoint, including the default `http://localhost:4318`, disables export. The Copilot CLI changelog for 1.0.106 says `copilot help monitoring` was corrected to say that only an OTLP CA certificate or client certificate variable does that. That's what gh-ledger documents and `status` checks. 1.0.115 sent its spans to `http://localhost:4318` and logged no warning.
- **Tool approval in prompt mode:** to keep a test prompt to the tools it names, deny the rest with `--deny-tool`; otherwise the model can reach for any configured MCP server's tools, as in q3.

## Reproduce

For more on these steps, see [Install and uninstall](../cli.md#install-and-uninstall) and [Repairs](../cli.md#repairs).

1. Stop the daemon, close the Copilot sessions and apps that use the `ledger` MCP server, and copy the data directory:

   ```powershell
   gh ledger daemon stop
   Copy-Item -Recurse "$HOME\.copilot-ledger" "$HOME\copilot-ledger-backup"
   ```

2. Upgrade, and verify the binary:

   ```powershell
   gh extension upgrade ledger
   gh ledger --version
   gh attestation verify "$env:LOCALAPPDATA\GitHub CLI\extensions\gh-ledger\gh-ledger.exe" --repo swigerb/gh-ledger --signer-workflow swigerb/gh-ledger/.github/workflows/release.yml
   ```

3. From a regular terminal, start the daemon, then repair the history once:

   ```powershell
   gh ledger daemon start
   gh ledger status
   gh ledger import --all
   ```

4. To go back: stop the daemon, run `gh extension remove ledger` and `gh extension install swigerb/gh-ledger --pin v0.5.0`, put the copy in place of `%USERPROFILE%\.copilot-ledger`, and start the daemon.
